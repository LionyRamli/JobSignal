# Phase 1.3: Harmonization - Design (short)

**Intent:** turn raw ATS titles and location strings into a small canonical taxonomy, so that
Phase 1.4 can count hiring by *role family × seniority × place*. That is how "Stripe opened 40
Solutions Engineering roles in Singapore this month" becomes detectable across companies that
word things differently.

**Brief:** "Data Harmonization: NLP-based job role and location classification" (spaCy + rules).

## Findings from the real data (2,322 postings: Anthropic, Databricks, Stripe; 2026-11-01)
- **Title vocabulary:** top words are engineer 675, manager 552, software 344, account 289, executive 286, architect 241, solutions 241, sr 235, staff 233, product 203.
- **"Manager" is mostly IC:** Product/Program/Account/Partner Manager. **"Executive"** is mostly *Account Executive*. Neither may be read as seniority by keyword alone.
- **Seniority tokens:** staff 294 (incl. `Staff+`), sr 235, senior 151, lead 102, director 58, intern 30, head 28, new grad 20, principal 16.
- **Locations are lists:** `|` in 376 strings, `;` in 263, plus ` or ` and `/`. There are 401 distinct pieces. Formats:
  - `City, ST`, `City, State`, `City, Country`
  - `Country`
  - `Remote - <State/Country>`, `Remote-Friendly[, <Country>]`
  - `<Macro-region> - United States`
  - `N/A`
- **Departments are informative** (`Enterprise Sales`, `AI Research & Engineering`, `Field Engineering - …`), but are company-specific and sometimes coded (`1185 Account Executives (EMEA)`).

## Taxonomy (version `2026.11.1`)
**Role families (16):**
- `software_engineering`, `ml_research`, `data`, `solutions_engineering`, `security`
- `product_management`, `program_management`, `design`
- `sales`, `customer_success`, `marketing`
- `operations`, `finance`, `legal`, `people`
- `other`

**Seniority (ordered):** `intern` < `entry` < `mid` < `senior` < `staff_plus` < `manager` < `director_plus`.
- No seniority signal → `mid`.
- **Precedence** when several signals match: intern > director_plus > manager > staff_plus > senior > entry > mid.
- `manager` means people-manager only via explicit patterns (`engineering manager`, `<team> manager` for research, design and similar teams, `team lead`, a leading `Manager, …`). IC-manager titles (product/program/project/account/partner/customer-success manager) don't count.
- `executive` is never a seniority signal; `vp`/`vice president`/`chief`/`head of`/`director` → director_plus.

**Locations:** `CanonicalLocation(kind, country_code, region_code, city)`
- `kind` is one of `city | region | country | remote`.
- Codes are ISO 3166-1 alpha-2 / ISO 3166-2 (e.g. `US`, `US-CA`).
- Remote pieces keep their region/country when stated (`Remote - California` → remote, US, US-CA).
- US macro-regions (`Northeast - United States`) resolve to country US.
- `Washington, DC` / `Washington D.C.` → `US-DC`; bare `Washington` → `US-WA`.
- Unresolvable pieces (`N/A`, typos) are reported, never guessed.

## Approaches
1. **spaCy rule pipeline + curated data files (chosen, assistant's call).**
   - Uses `spacy.blank("en")`: the tokenizer plus `PhraseMatcher(attr="LOWER")`, run over phrase lists kept in TOML data files, and a gazetteer for places.
   - Deterministic and explainable: every result lists the phrases that matched.
   - Needs no model download, so CI runs it; it's fast (thousands of titles per second).
2. spaCy statistical NER (`en_core_web_sm`) as a location fallback.
   - Downloads about 12 MB and is non-deterministic across versions.
   - It only finds *that* something is a place; the gazetteer is still needed to resolve it to codes. Deferred.
3. Trained text classifier (spaCy `textcat`).
   - Best ceiling, but needs hundreds of labelled examples per family first.
   - The golden set built here is the seed for it (Phase 2).

## Decisions (assistant's calls - flag any to change)
- **Where the taxonomy lives:** in `src/jobsignal/harmonization/data/*.toml`, read with stdlib `tomllib`, so rules change without code changes. Every result records `TAXONOMY_VERSION`.
- **How the title is used:** the title decides first; the department is a fallback for family only (never for seniority).
- **Storage:**
  - New nullable columns on `postings`: `role_family`, `seniority`, `taxonomy_version`, `harmonized_at`.
  - New `locations` table (unique canonical key) and `posting_locations` join table.
- **When it runs:** a separate `harmonize` command processes postings whose `taxonomy_version` is missing or outdated, so a rule change reprocesses everything with no re-scrape. The scrape command is unchanged; Phase 1.4's pipeline will chain them.
- **Quality gate:** a hand-labelled golden set of **200 real titles** and **150 real location pieces**, sampled from the live DB and committed as CSV fixtures. Tests require:
  - **family accuracy ≥ 90 %** and **seniority accuracy ≥ 90 %**;
  - **≥ 95 % of location pieces resolved** to the labelled value.
- **Overfitting guard:** the labels are the assistant's, so the user should spot-check them. A held-out 25 % split is reported separately so tuning on the rest is visible.
- **New dependency:** `spacy>=3.8,<4` (pure rules use, no model). The intake checklist is answered in the PR.
