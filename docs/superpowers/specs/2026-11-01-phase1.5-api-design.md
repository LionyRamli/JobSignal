# Phase 1.5: API - Design (short)

**Intent:** a read-only HTTP API over the JobSignal database. It serves companies, postings
(with harmonized role, seniority and locations) and signal runs and scores (raw z, the
postings behind each signal). The Phase 1.6 Streamlit dashboard, and later clients, can then
read data without touching SQLite or the pipeline code.

**Brief:** "Backend/Storage: FastAPI (for API delivery)".

## Goals / non-goals / anti-goals
- **Goals:** stable JSON contract (OpenAPI auto-docs); filters and keyset pagination; drill-down
  from a signal to its postings; health that tells *why* the API cannot serve (no schema).
- **Non-goals:**
  - no writes, and no triggering of scrape/harmonize/detect over HTTP (those stay CLI and
    scheduled jobs);
  - no user accounts;
  - no WebSockets.
- **Anti-goals:**
  - leaking stack traces or DB paths in error bodies;
  - an API reachable from the network without a key;
  - NaN/Infinity in JSON. Those are invalid JSON and would break the dashboard.

## Endpoints (all `GET`, JSON, prefix `/api/v1`)
| Path | Returns |
|------|---------|
| `/health` | `{"status": "ok" \| "schema_missing", "taxonomy_version", "signals_version"}`; 503 when the schema is missing |
| `/meta` | Taxonomy enums (families, seniorities, location kinds), signal levels, detectors and versions, for dashboard filters |
| `/companies` | Every company with `open_postings`, `last_snapshot_at`, `last_snapshot_status` |
| `/companies/{board_token}` | The same for one company (404 if unknown) |
| `/postings` | Filters: `company`, `role_family`, `seniority`, `country`, `open` (bool, default true), `limit` (1–200, default 50), `cursor`. Returns `{items, next_cursor}` with keyset pagination by id |
| `/postings/{id}` | One posting with its canonical locations and open/close history fields |
| `/signal-runs` | Runs, newest `as_of` first, with params and versions (`limit` ≤ 200) |
| `/signals` | Scores of one run: `run` = `latest` (default, newest as_of) or an id. Filters: `detector`, `direction`, `level`, `company`, `min_abs_z`, `signals_only` (default true), `limit` (≤ 500). Each item has the raw z / observed / baseline values, `share_recent` / `share_baseline` for mix_shift and a `provisional` flag |
| `/signals/{id}` | One score, its run params and `postings` (the drill-down: id, title, url, locations) |

## Decisions (assistant's calls - flag any to change)
- **Code layout:** `api/` has `app.py` (the `create_app(database_url=None) -> FastAPI` factory),
  `deps.py` (engine at startup via lifespan, one session per request), `schemas.py` (Pydantic
  response models, separate from the ORM) and `routes/` (one module per resource).
- **Security defaults:**
  - Binds `127.0.0.1` by default.
  - Binding any other host **requires** `JOBSIGNAL_API_KEY`, and the server refuses to start
    without it.
  - With a key set, every route except `/health` needs the `X-API-Key` header, compared in
    constant time (401 otherwise).
  - CORS is off unless `JOBSIGNAL_API_CORS_ORIGINS` is set.
  - Unhandled errors return `{"detail": "internal error"}` and are logged server-side.
- **Encoding:** timestamps are ISO-8601 UTC with `Z`. Floats are finite or `null`, validated in
  the response models.
- **Pagination:** an opaque cursor (urlsafe base64 of the last id). Bad cursors are rejected
  with 422.
- **Query shape:** queries live in `storage/repository.py` (still the only DB access layer) and
  use eager loading, so there are no N+1 queries.
- **New dependencies:** `fastapi`, `uvicorn` (runtime). Tests use FastAPI's `TestClient`
  (httpx is already present).
- **Run command:** `uv run python scripts/run_api.py [--host 127.0.0.1] [--port 8000]`.
