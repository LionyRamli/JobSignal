# Phase 1.3: Harmonization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Classify every stored posting's title into a role family and seniority, and its location string into canonical locations, then persist the results with a taxonomy version.

**Architecture:**
- `harmonization/` holds three pure modules:
  - `taxonomy.py` loads and validates the TOML rule data.
  - `roles.py` is a spaCy `PhraseMatcher` classifier.
  - `locations.py` is a splitter plus gazetteer resolver.
- The pure modules know nothing about the database. `storage/repository.py` gains read/write functions, and a `harmonize` command connects them in batches.
- A committed golden set of real, hand-labelled examples gates accuracy in CI.

**Tech Stack:** Python 3.12, spaCy 3.8 (`spacy.blank("en")`, no model), stdlib `tomllib`, SQLAlchemy/Alembic, pytest.

**Spec:** `docs/superpowers/specs/2026-11-01-phase1.3-harmonization-design.md`

## Global Constraints

- **Taxonomy:** exactly the 16 role families, 7 seniority levels and location kinds listed in the spec. `TAXONOMY_VERSION = "2026.11.1"`.
- **New dependency:** only `spacy>=3.8,<4`. No spaCy model downloads anywhere, including CI. The `spacy.blank("en")` pipeline is built once per process.
- **Purity:** classifiers are pure functions. The same input and the same taxonomy version always give the same output.
- **Reporting:** every result carries the phrases that matched (`evidence`).
- **Locations:** unresolved pieces are reported, never guessed. Codes are ISO 3166-1 alpha-2 / ISO 3166-2.
- **Schema:** changes go through a new Alembic migration on top of `475ab77726f0`, and the drift test must stay green.
- **Gates:** UTF-8 for all file I/O; ruff, format and pytest green per task; commits pass the gitleaks hook.

## Review Focus

1. **IC "Manager" and "Executive" titles.**
   - `Product Manager, Claude Marketplace` → product_management/mid.
   - `Enterprise Account Executive, Automotive` → sales/mid.
   - `Sr. Engineering Manager` → software_engineering/manager.
   - *(Task 2: `test_ic_manager_titles_are_not_people_managers`, `test_account_executive_is_not_an_executive`)*
2. **Mixed separators with remote pieces.** `California; New York; Remote - Colorado | US-Remote` → 4 distinct locations, with remote pieces keeping their region and duplicates removed. *(Task 3: `test_mixed_separators_and_remote_pieces`)*
3. **Washington.** `Washington, DC`, `Washington D.C.` and `Remote - Washington D.C.` → US-DC; `Seattle, Washington` and `Remote - Washington` → US-WA. *(Task 3: `test_washington_dc_vs_state`)*
4. **Rule change.** Bumping `TAXONOMY_VERSION` reprocesses already-harmonized postings. Re-running at the same version touches nothing. *(Task 5: `test_rerun_same_version_is_noop`, `test_version_bump_reprocesses`)*
5. **Junk input.** `""`-adjacent junk titles (`"???"`, emoji, Japanese text) and `None` departments → `other`/`mid` with empty evidence, no exception. A `None` or `"N/A"` location → zero locations, one unresolved piece at most. *(Task 2: `test_junk_titles_fall_back_safely`; Task 3: `test_missing_and_na_locations`)*

### Task 2: Title classifier + golden titles

**Files:**
- Create:
  - `src/jobsignal/harmonization/roles.py`
  - `tests/fixtures/harmonization/golden_titles.csv` (`title,department,family,seniority,split`)
  - `scripts/sample_golden.py`
- Test: `tests/unit/harmonization/test_roles.py`, `tests/unit/harmonization/test_golden_titles.py`

**Interfaces:**
- Consumes: `load_taxonomy`, enums (Task 1).
- Produces:
  - `@dataclass(frozen=True) RoleClassification`: `family: RoleFamily`, `seniority: Seniority`, `evidence: tuple[str, ...]`.
  - `classify_title(title: str, department: str | None = None) -> RoleClassification`.
- Algorithm:
  1. Tokenize with a module-level `spacy.blank("en")`. Run `PhraseMatcher(attr="LOWER")` per phrase table.
  2. **Family:** the most specific (longest) title match wins. If there is no title match, use the department phrases. Otherwise `other`.
  3. **Seniority:** collect the matches, then remove `manager` hits that fall inside an IC-manager phrase span. Pick the highest by `SENIORITY_PRECEDENCE`; default `mid`.
  4. **Evidence:** the matched phrases in the order they appear.

  - Mark `split=holdout` on a random 25 % (seed 13). Holdout rows are never used to tune rules.
  - Commit the CSV with a header comment naming the labeller (assistant) and the date.
- [ ] **Step 2: Write failing tests.**

### Task 3: Location parser + golden pieces

**Files:**
- Create: `src/jobsignal/harmonization/locations.py`, `tests/fixtures/harmonization/golden_locations.csv` (`piece,kind,country_code,region_code,city,split`)
- Test: `tests/unit/harmonization/test_locations.py`, `tests/unit/harmonization/test_golden_locations.py`

**Interfaces:**
- Consumes: `load_taxonomy` (Task 1).
- Produces:
  - `class LocationKind(StrEnum)`: `city`, `region`, `country`, `remote`.
  - `@dataclass(frozen=True) CanonicalLocation`: `kind`, `country_code: str | None`, `region_code: str | None`, `city: str | None`, with property `key -> str`, e.g. `"remote|US|US-CA|"`.
  - `@dataclass(frozen=True) LocationParse`: `locations: tuple[CanonicalLocation, ...]` (deduplicated, input order), `unresolved: tuple[str, ...]`.
  - `parse_locations(raw: str | None) -> LocationParse`.
  - `split_pieces(raw: str) -> list[str]`. It splits on `|`, `;`, ` or ` and `/` (not inside `D.C.`), then strips and drops empties.
- Resolution order per piece:
  1. Unresolvable marker → unresolved.
  2. Remote marker prefix → remote + resolve the rest as region/country.
  3. `City, X` via the cities table, with X matching a region or country.
  4. Bare city alias.
  5. Region alias.
  6. Macro-region.
  7. Country alias.
  8. Otherwise unresolved.

- [ ] **Step 1: Build the golden pieces.** The 150 most frequent real pieces, labelled by hand, with `split=holdout` on 25 %.
- [ ] **Step 2: Write failing tests.**
  - `test_mixed_separators_and_remote_pieces`: `California; New York; Remote - Colorado | US-Remote` → keys `["region|US|US-CA|", "region|US|US-NY|", "remote|US|US-CO|", "remote|US||"]`.
  - `test_washington_dc_vs_state` (5 inputs from Review Focus 3).
  - `test_city_forms_agree`: `San Francisco, CA`, `San Francisco, California` and `San Francisco` → the same key, `city|US|US-CA|San Francisco`. Likewise for `Bengaluru, India` and `Bangalore` (IN, IN-KA).
  - `test_country_and_macro_region`: `United States`, `US` and `Northeast - United States` → `country|US||`; `London, UK` → `city|GB|GB-ENG|London`.
  - `test_remote_friendly_variants`: `Remote-Friendly (Travel-Required)` → `remote|||`; `Remote-Friendly, Australia` → `remote|AU||`.
  - `test_missing_and_na_locations`: `None` → `LocationParse((), ())`; `"N/A"` → `((), ("N/A",))`.
  - `test_duplicates_removed_order_kept`.
  - `test_golden_locations_meet_threshold`: ≥ 95 % exact match per split. The message lists the misses.
