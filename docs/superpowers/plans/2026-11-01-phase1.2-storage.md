# Phase 1.2: Storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist every scrape run, per-company snapshot and posting to SQLite with an exact open-postings history, and make the scrape CLI write to it.

**Architecture:**
- SQLAlchemy 2.0 ORM tables live in `storage/schema.py`. Alembic owns DDL, and the existing drift test keeps the two in sync.
- `storage/repository.py` is the only code that reads or writes these tables. It exposes a few lifecycle functions (start run → record snapshot / failure → finish run). These are called by `scrape.py`, which commits after each company.
- A `UTCDateTime` type guarantees that times are timezone-aware and in UTC across SQLite and PostgreSQL.

**Tech Stack:** Python 3.12, SQLAlchemy 2.x, Alembic, pytest, uv, ruff.

**Spec:** `docs/superpowers/specs/2026-11-01-phase1.2-storage-design.md`

## Global Constraints

- No new runtime dependencies.
- Schema changes are made only via an Alembic migration. `tests/integration/test_migrations.py::test_models_match_migrated_schema` must stay green.
- Tests use a real SQLite file under `tmp_path`, migrated with `alembic upgrade head`. No mocking the DB. No live network.
- All timestamps are timezone-aware. Storage is UTC. Naive datetimes are rejected.
- Status values: runs use `running|succeeded|partial|failed`; snapshots use `ok|failed`.
- Encoding: `encoding="utf-8"` on every file read/write. Logging: INFO for the run lifecycle, ERROR for a failed company.
- Gates per task: `uv run ruff check .`, `uv run ruff format --check .`, `uv run pytest` all exit 0. Commits go through the gitleaks pre-commit hook; never use `--no-verify`.

## Review Focus

1. **Failed fetch after a good one** (company had 10 open postings; the next run's fetch 503s) → all 10 stay open; only a `failed` snapshot is added. *(Task 4: `test_failed_snapshot_closes_nothing`)*
2. **Posting disappears then reappears** → `closed_at` is set at the gap and cleared on return, and `first_seen_at` is unchanged. *(Task 4: `test_reopened_posting_clears_closed_at_keeps_first_seen`)*
3. **Timezone round-trip** (`2024-04-23T16:06:05-04:00`) → read back as the same instant, aware, in UTC. A naive datetime raises on write. *(Task 1: `test_offset_datetime_round_trips_as_utc`, `test_naive_datetime_rejected_on_write`)*
4. **Same company twice in one CLI run** (`anthropic anthropic`) → one snapshot and no IntegrityError. *(Task 5: `test_duplicate_company_args_scraped_once`)*
5. **Fresh clone without `alembic upgrade head`** → the CLI exits 2 with a message naming the command, not a raw `OperationalError` traceback. *(Task 5: `test_unmigrated_database_exits_2_with_hint`)*

### Task 1: UTCDateTime column type + session factory

**Files:**
- Create: `src/jobsignal/storage/types.py`
- Modify: `src/jobsignal/storage/db.py`
- Test: `tests/unit/storage/test_types.py`, `tests/unit/storage/test_db.py`

**Interfaces:**
- Produces:
  - `class UTCDateTime(TypeDecorator[datetime])`: `impl = DateTime(timezone=True)`, `cache_ok = True`.
    - On write: `None` passes through. A naive value raises `ValueError("naive datetime")`. Otherwise the value is converted to UTC; on SQLite it is stored with `tzinfo` stripped.
    - On read: returns an aware UTC datetime (or `None`).
  - `make_session_factory(engine: Engine) -> sessionmaker[Session]` in `db.py` (`expire_on_commit=False`).

  - `test_naive_datetime_rejected_on_write`: raises (`StatementError` wrapping `ValueError`).
  - `test_none_round_trips`.
  - `test_session_factory_does_not_expire_on_commit`: commit, then access an attribute without a refresh query. Use `sqlalchemy.event` to count `before_cursor_execute` events; the count must be 0 after the commit.

### Task 4: Repository – snapshots (upsert, membership, close, reopen)

**Files:**
- Modify: `src/jobsignal/storage/repository.py`
- Test: `tests/integration/test_repository_snapshots.py`

**Interfaces:**
- Consumes: Task 3 functions; `jobsignal.models.Posting`.
- Produces:
  - `record_snapshot(session, run: ScrapeRun, company: Company, postings: list[Posting], fetched_at: datetime) -> Snapshot`. Applies the spec's "Successful snapshot" rules. `posting_count = len(postings)` after deduplicating by `external_id`. Raises `ValueError` if any `posting.company != company.board_token` or `posting.source != company.source`.
  - `record_failed_snapshot(session, run, company, error_type: str, fetched_at: datetime) -> Snapshot`

### Task 5: Persist from the scrape CLI

**Files:**
- Modify: `src/jobsignal/scrape.py`
- Test: `tests/integration/test_run_scrape.py` (extend), `tests/integration/test_scrape_persistence.py`

**Interfaces:**
- Consumes: Tasks 3–4; `make_engine`, `make_session_factory`.
- Produces: `main(argv, transport=None, min_interval=None) -> int`. New flags: `--db URL` (default: settings `database_url`); `--out` is now optional (JSONL is written only when given).
- Exit codes: 0 = all ok; 1 = any company failed; 2 = DB schema missing.
- Flow:
  1. Dedupe company args, preserving order.
  2. Check that the `alembic_version` table exists. If not, log ERROR `run: uv run alembic upgrade head` and return 2.
  3. `start_run` → commit.
  4. Per company: fetch → `record_snapshot` (or `record_failed_snapshot` with `type(exc).__name__`) → commit.
  5. `finish_run` → commit.
