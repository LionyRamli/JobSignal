# Phase 1.4: Signal Detection Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score weekly hiring per company × role family × country against rolling baselines and persist **expansion and contraction** signals with raw z and baseline values: `volume` on observed new openings, `mix_shift` (provisional) on published-date shares.

**Architecture:**
- **Pure pandas functions in `signals/`:**
  - `events.py` turns DB rows into opening events.
  - `features.py` builds cell × week counts with missing-week masks.
  - `detectors.py` implements the two scorers.
- **Thin DB layers:**
  - `storage/repository.py` reads events and writes runs and scores.
  - A `detect` command wires it all together.
- **Testing:** the statistics are tested on synthetic series with hand-computed expectations. The DB path is tested on a migrated SQLite file.

**Tech Stack:** Python 3.12, pandas (new), SQLAlchemy/Alembic, pytest.

**Spec:** `docs/superpowers/specs/2026-11-01-phase1.4-signals-design.md`

## Global Constraints

- **New dependency:** only `pandas>=2.2,<3`.
- **Parameter defaults are exactly the spec's values.** `DetectorParams` defaults: `baseline_weeks=8`, `volume_min_count=5`, `z_threshold=3.0`, `contraction_z_threshold=-3.0`, `contraction_min_baseline=5.0`, `strong_z=4.0` (applied to |z|), `recent_weeks=4`, `mix_baseline_weeks=12`, `mix_min_recent=5`, `mix_min_company_baseline=30`. `SIGNALS_VERSION = "2026.11.1"`.
- **Week and level conventions:**
  - Weeks are ISO weeks, Monday 00:00 UTC. Only complete weeks before `as_of` are scored.
  - Levels are `company`, `company_family`, `company_country`, `company_family_country`.
  - The unknown-country code is `ZZ`.
- **Numeric safety:** never emit `inf` or `NaN` z-scores. Rows that can't be scored get `status != "scored"` and `z = NULL`.
- **Signals:** expansions (z ≥ 3) and contractions (z ≤ −3, μ ≥ 5). A volume week is available only when the company had an **`ok`** snapshot that week.
- **Gates:** UTF-8 I/O; ruff, format and pytest green per task; commits go through the gitleaks hook.

## Review Focus

1. **Initial-load spike.** The company's first successful snapshot shows 2,322 postings at once; none of them is a "new opening". Only postings first seen *after* that snapshot count. *(Task 1: `test_first_snapshot_postings_are_not_new_openings`)*
2. **Survivorship ramp.** A published-date history that grows uniformly across all of a company's cells → zero `mix_shift` signals. *(Task 3: `test_uniform_growth_is_not_a_mix_shift`)*
3. **Sparse or zero-variance baselines.** `[0,0,0,0,0,0,0,0] → 1` → finite z, no signal (`min_count`). `[0]*8 → 6` → finite z ≥ 3 and a signal. *(Task 3: `test_zero_variance_baseline_is_finite`, `test_single_posting_is_never_a_signal`)*
4. **Partial current week.** With `as_of` on a Wednesday, that week is not scored; the last scored week is the previous one. *(Task 2: `test_partial_week_is_not_scored`)*
5. **Scrape outage or partial-only week.** A week with no **`ok`** snapshot for the company is *missing*. This covers failed weeks and weeks with only `partial` snapshots, since a partial fetch under-counts new openings and would fake a freeze. Missing weeks are excluded from baselines and never scored. *(Task 1: `test_observed_weeks_requires_ok_snapshot`; Task 2: `test_outage_week_is_missing_not_zero`; Task 3: `test_missing_weeks_excluded_from_baseline`)*
6. **Freeze on a tiny cell.** A baseline of `[1]*8 → 0` gives z = −1, so no contraction. A baseline of `[12]*8 → 0` gives a strong contraction. *(Task 3: `test_tiny_cells_cannot_fake_a_freeze`, `test_contraction_flagged`)*

### Task 3: Detectors

**Files:**
- Create: `src/jobsignal/signals/detectors.py`
- Test: `tests/unit/signals/test_detectors.py`

**Interfaces:**
- Consumes: `cell_counts` output, `DetectorParams`.
- Produces:
  - `volume_scores(counts: pd.DataFrame, params: DetectorParams) -> pd.DataFrame`.
    - One row per cell × week with `available`: `observed`, `baseline_mean`, `baseline_std`, `baseline_weeks`, `z`, `status`, `is_signal`, `severity`.
    - The baseline is the previous `baseline_weeks` *available* weeks of that cell, excluding the current week.
  - `mix_shift_scores(counts: pd.DataFrame, level: str, params: DetectorParams) -> pd.DataFrame`.
    - One row per cell, for the last `recent_weeks` vs the `mix_baseline_weeks` before them, with the same columns. `observed` = `n_r`, `baseline_mean` = `n_b`.
    - The company totals for `N_r`/`N_b` come from the same `counts`, summed per company.
    - Not defined for level `company` (always share 1) → returns no rows.
  - Statuses: `insufficient_history` (baseline shorter than required, or `N_b < mix_min_company_baseline`); `below_min_count`; `scored`. `z` is NULL unless `scored`.

- [ ] **Step 1: Write failing tests.** Expected values are hand-computed in the test docstrings.
  - `test_volume_z_matches_hand_computation`: baseline `[4,6,5,5,4,6,5,5]`, x = 12. Then μ = 5, s² = 0.571 → σ_eff = sqrt(max(0.571, 5, 1)) = 2.236 → z = 3.130 → signal, notable.
  - `test_zero_variance_baseline_is_finite`: `[0]*8 → 6` → z = 6.0 (σ_eff = 1), strong.
  - `test_single_posting_is_never_a_signal`: `[0]*8 → 1` → `below_min_count`, `is_signal` False.
  - `test_insufficient_history`: 5 available weeks → status `insufficient_history`, z None.
  - `test_missing_weeks_excluded_from_baseline`: 10 weeks with 2 missing → the baseline uses the 8 available weeks before the current one. A missing current week → no row.
  - `test_contraction_flagged`: `[12]*8 → 0`. Then μ = 12, σ_eff = √12 = 3.464, z = −3.464 → `is_signal`, `direction == "contraction"`, severity `notable`. `[20]*8 → 0` gives z = −4.47 → `strong`.
  - `test_tiny_cells_cannot_fake_a_freeze`: `[1]*8 → 0` gives z = −1.0, not a signal. `[4]*8 → 0` gives μ < `contraction_min_baseline`, not a signal.
  - `test_mix_shift_contraction`: n_r = 2, N_r = 100, n_b = 30, N_b = 150 → z ≤ −3 → contraction, provisional basis `published`.
  - `test_raw_values_kept_for_non_signals`: a scored, non-signal row still carries finite `z`, `observed`, `baseline_mean` and `baseline_std`.
  - `test_mix_shift_matches_hand_computation`: n_r = 15, N_r = 50, n_b = 10, N_b = 150 → p = 0.125 and z = (0.3 − 0.0667) / sqrt(0.125 × 0.875 × (1/50 + 1/150)) = 4.32 → strong.
  - `test_uniform_growth_is_not_a_mix_shift`: every cell ×4 in the recent window → all z ≈ 0.
  - `test_mix_shift_needs_company_baseline` (N_b = 20 → `insufficient_history`).
  - `test_no_inf_or_nan_anywhere`: a property-style loop over 500 random small-count frames (seeded) asserts every z is a finite number or None.
- [ ] **Step 2: Run** → FAIL. **Step 3:** implement (vectorized per cell; `numpy` for sqrt/max). **Step 4:** PASS; gates; mutation-check the σ floor, the min-count rule, missing-week exclusion, both direction thresholds and the contraction baseline floor.
- [ ] **Step 5: Commit** `feat(signals): volume z-score and mix-shift detectors`

### Task 4: Storage for runs and scores

**Files:**
- Modify: `src/jobsignal/storage/schema.py`, `src/jobsignal/storage/repository.py`
- Create: `alembic/versions/<rev>_signals.py` (autogenerate on top of `c50c110ac0ba`)
- Test: `tests/integration/test_repository_signals.py`

**Interfaces:**
- Produces:
  - **ORM `SignalRun`:** `id`, `computed_at` UTCDateTime, `as_of` UTCDateTime, `signals_version` str(16), `params` Text.
  - **ORM `SignalScore`:**
    - Keys: `id`, `run_id` FK, `detector` str(16) CHECK in (`volume`, `mix_shift`), `basis` str(16) CHECK in (`observed`, `published`), `level` str(32) CHECK in LEVELS.
    - Cell: `company_id` FK, `role_family` str(32) | None, `country_code` str(2) | None, `week_start` Date.
    - Scores: `observed` float, `baseline_mean` float | None, `baseline_std` float | None, `baseline_weeks` int, `z` float | None.
    - Outcome: `status` str(24) CHECK, `is_signal` bool, `direction` str(16) | None CHECK in (`expansion`, `contraction`), `severity` str(16) | None. Raw `z`/`observed`/`baseline_*` are stored for every scored row (dashboard colour bands use raw z).
    - Indexes: (`run_id`, `is_signal`) and (`company_id`, `level`, `week_start`).
  - `save_signal_run(session, computed_at, as_of, params: DetectorParams, scores: pd.DataFrame) -> SignalRun`.
    - Bulk insert. It maps the company name to its id and requires the score frame's columns exactly.
    - A non-finite z raises `ValueError` before writing.
  - `latest_signals(session, limit: int = 50) -> list[SignalScore]`: from the newest run, `is_signal` rows ordered by |z| desc.

### Task 5: `detect` command + live run

**Files:**
- Create: `src/jobsignal/detect.py`, `scripts/run_detect.py`
- Test: `tests/integration/test_detect_cli.py`

**Interfaces:**
- Consumes: everything above; `schema_ready`.
- Produces: `main(argv: list[str] | None = None, now: Callable[[], datetime] | None = None) -> int`.
  - Flags: `--as-of YYYY-MM-DD` (default: now), `--db URL`.
  - Exit codes: 0, or 2 when the schema is missing.
  - Pipeline:
    1. Events for both bases.
    2. For each level: volume on observed with `available=observed_weeks`, over `scored_weeks(as_of, baseline_weeks + 1)`; mix shift on published over `scored_weeks(as_of, recent_weeks + mix_baseline_weeks)`, with `available=None`.
    3. Concatenate, then `save_signal_run`.
  - Logs one INFO summary: `run_id`, counts by detector × status, signals by direction, and the top 5 signals by |z| (`company/level/cell z`).

- [ ] **Step 1: Write failing tests.** The migrated DB is seeded with synthetic snapshots over 10 weeks via the repository; `now` is injected.
  - `test_volume_spike_detected_end_to_end`: steady 2/week in (acme, sales, US), then 9 in the last complete week → exactly one `volume` signal at level `company_family_country` for that cell.
  - `test_cold_start_reports_insufficient_history`: 1 snapshot → 0 volume signals, every volume row `insufficient_history`, exit 0.
  - `test_unmigrated_db_exits_2`.
  - `test_each_run_is_new` (two invocations → 2 runs).
- [ ] **Step 2: Run** → FAIL. **Step 3:** implement. **Step 4:** PASS; gates.
- [ ] **Step 5: Live run (manual).** `uv run alembic upgrade head && uv run python scripts/run_detect.py` on the local DB. Record in the ledger:
  - volume: all `insufficient_history` (expected: there is one run of history);
  - the number of mix-shift signals by company;
  - the top 10 mix-shift signals, each with a one-line plausibility note from the posting titles behind it (e.g. "stripe / sales / IE: Dublin EMEA sales team build-out").
  
  If more than 15 % of a company's cells signal, treat it as a calibration smell: stop, and report the distribution rather than tuning thresholds to taste.
