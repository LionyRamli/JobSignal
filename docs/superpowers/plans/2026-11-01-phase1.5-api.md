# Phase 1.5: API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only FastAPI service exposing companies, postings and signals (with drill-down) from the JobSignal database, safe by default.

**Architecture:**
- **App factory:** `create_app(database_url)` builds the engine in a lifespan hook and hands one SQLAlchemy session per request through a dependency.
- **Thin routes:** route modules call repository query functions and return Pydantic response models (never ORM objects).
- **Security middleware:** optional API key, mandatory off-localhost; CORS off; a generic 500 handler.

**Tech Stack:** Python 3.12, FastAPI, uvicorn, Pydantic v2, SQLAlchemy 2, pytest + `fastapi.testclient.TestClient`.

**Spec:** `docs/superpowers/specs/2026-11-01-phase1.5-api-design.md`

## Global Constraints

- **New dependencies:** only `fastapi>=0.115,<1` and `uvicorn>=0.30,<1`.
- **Read-only:** every route is `GET` under `/api/v1`. No route writes to the DB.
- **Limits:** `/postings` limit 1–200 (default 50); `/signal-runs` ≤ 200; `/signals` ≤ 500.
- **JSON shape:** datetimes are ISO-8601 UTC ending in `Z`. Floats are finite or `null`, so JSON never contains NaN or Infinity.
- **Errors:** 404 `{"detail": "<resource> not found"}`; 422 for invalid params (FastAPI default); 401 `{"detail": "invalid or missing API key"}`; 503 `{"detail": "database schema missing; run: uv run alembic upgrade head"}`; 500 `{"detail": "internal error"}` (logged with the traceback server-side, never returned).
- **Security:**
  - The key is read from `JOBSIGNAL_API_KEY` and compared with `hmac.compare_digest`.
  - The run script refuses a non-loopback `--host` without a key (exit 2).
- **Data access:** all queries go through `storage/repository.py`. Tests use migrated tmp SQLite files, as in earlier phases. No live network.
- **Gates:** ruff, format and pytest green per task; gitleaks hook on every commit.

## Review Focus

1. **Unmigrated or empty database.**
   - `/health` returns 503 `schema_missing`, and every other route returns 503 with the hint, not a 500 traceback.
   - A migrated but empty DB returns `[]` / `{"items": [], "next_cursor": null}` / `run: null`.
   - *(Task 1: `test_health_schema_missing`, `test_routes_503_without_schema`; Task 2: `test_empty_database_lists_are_empty`)*
2. **Hostile pagination and filters:** `limit=0`, `limit=10000`, `cursor=garbage`, `cursor=` a base64 negative number, `min_abs_z=nan` → 422, never a 500 or an unbounded query. *(Task 3: `test_bad_pagination_params_are_422`; Task 4: `test_min_abs_z_must_be_finite`)*
3. **Insufficient-history rows.**
   - Rows with `z` NULL serialise as `null`; mix-shift rows carry `provisional: true` and shares.
   - No NaN ever reaches the JSON body: the test parses the body with `json.loads(..., parse_constant=reject)`.
   - *(Task 4: `test_null_z_and_provisional_flags_serialise_cleanly`)*
4. **Unknown ids and tokens:** `/companies/nope`, `/postings/999999`, `/signals/999999`, `/signals?run=999999` → 404 JSON. *(Tasks 2–4: `test_unknown_*_is_404`)*
5. **Exposure.**
   - A non-loopback bind without a key fails to start.
   - With a key set: a missing or wrong `X-API-Key` → 401 on data routes; `/health` stays open; the right key → 200.
   - An unexpected exception → 500 `internal error` with no traceback in the body.
   - *(Task 5: `test_non_loopback_requires_key`, `test_api_key_enforced`, `test_internal_errors_are_opaque`)*

**Interfaces:**
- Produces:
  - `create_app(database_url: str | None = None) -> FastAPI`. The default URL comes from settings. The lifespan hook stores `app.state.engine` and `app.state.sessions`, and disposes the engine on shutdown. The router is mounted at `/api/v1`.
  - `deps.get_session(request) -> Iterator[Session]`, a FastAPI dependency (one session per request, always closed).
  - `deps.require_schema(request) -> None`: raises `HTTPException(503, …)` when `schema_ready(engine)` is false. It applies to every router except health.
  - `schemas.Health(status: Literal["ok","schema_missing"], taxonomy_version: str, signals_version: str)`.
  - `schemas.UTC_DATETIME`: an annotated datetime type that serialises as `YYYY-MM-DDTHH:MM:SS(.ffffff)Z`.
  - `schemas.FiniteFloat`: `float | None` that rejects NaN/±Inf in validation.
- Test fixtures:
  - `api_client(migrated_url)` yields `TestClient(create_app(migrated_url))` inside a `with` block, so the lifespan runs.
  - `seeded_api(migrated_url)` seeds 2 companies, postings (via `record_snapshot` + `save_harmonization`) and one signal run (via `save_signal_run`) with an expansion, a contraction, an insufficient-history row and a mix-shift row.

**Interfaces:**
- Produces:
  - `pagination.encode_cursor(last_id: int) -> str` and `decode_cursor(cursor: str) -> int`. Decoding raises `ValueError` on anything that isn't urlsafe base64 of a positive int; the route maps that to 422.

  - `schemas.PostingOut`: `id`, `company`, `external_id`, `title`, `department`, `location_raw`, `url`, `role_family`, `seniority`, `locations: list[LocationOut]`, `first_published`, `first_seen_at`, `last_seen_at`, `closed_at`.
  - `schemas.LocationOut`: `key`, `kind`, `country_code`, `region_code`, `city`.
  - `schemas.Page[T]`: `items`, `next_cursor: str | None`.
  - Routes: `GET /postings` (`limit` is `Query(50, ge=1, le=200)`; it fetches `limit + 1` rows to decide `next_cursor`) and `GET /postings/{id}`.

### Task 4: Signals, runs and drill-down

**Files:**
- Create: `src/jobsignal/api/routes/signals.py`
- Modify: `src/jobsignal/storage/repository.py`, `src/jobsignal/api/schemas.py`

**Interfaces:**
- Consumes: `latest_signals` semantics (newest `as_of`); `signals.drilldown.postings_for_score`.
- Produces:
  - `repository.list_signal_runs(session, limit: int) -> list[SignalRun]`, newest `as_of` first.
  - `repository.resolve_run(session, run: str) -> SignalRun | None`. `"latest"` or a positive int string; anything else raises `ValueError`, which becomes 422.
  - `repository.list_scores(session, run_id: int, *, detector, direction, level, company, min_abs_z: float | None, signals_only: bool, limit: int) -> list[tuple[SignalScore, str]]` (the score and the company token), ordered by |z| desc with nulls last, then id.
  - `schemas.SignalOut`:

  - `schemas.SignalRunOut`: `id`, `computed_at`, `as_of`, `signals_version`, `taxonomy_version`, `params` (parsed JSON dict).
  - `schemas.SignalsPage`: `run: SignalRunOut | None`, `items: list[SignalOut]`.
  - `schemas.SignalDetail`: `signal`, `run`, `postings: list[PostingBrief]` (`id`, `title`, `url`, `locations`).
  - Routes: `GET /signal-runs`, `GET /signals`, `GET /signals/{id}`.

### Task 5: Security, run script, live smoke

**Files:**
- Create: `src/jobsignal/api/security.py`, `scripts/run_api.py`, `src/jobsignal/api/serve.py`
- Modify: `src/jobsignal/api/app.py`, `src/jobsignal/config.py` (`api_key: SecretStr | None`, `api_cors_origins: list[str] = []`)
- Test: `tests/integration/api/test_security.py`, `tests/unit/api/test_serve.py`

**Interfaces:**
- Produces:
  - **API key:** `security.api_key_dependency(settings) -> Callable`. A router-level dependency on all data routers (not health). It does nothing when no key is configured; otherwise it checks `X-API-Key` with `hmac.compare_digest` and raises 401.
  - **500 handler:** `app.exception_handler(Exception)` returns `{"detail":"internal error"}` with status 500 and logs `logger.exception`.
  - **CORS:** `CORSMiddleware` is added only when `api_cors_origins` is set, allowing `GET` only.
  - **Server:** `serve.main(argv) -> int`, flags `--host` (default `127.0.0.1`) and `--port` (default 8000).
    - If the host is not loopback (`ipaddress.ip_address(host).is_loopback` is false, or the host is not `localhost`) and no key is set: log ERROR and return 2.
    - Otherwise run `uvicorn.run(create_app(), host, port)`.

- [ ] **Step 1: Write failing tests.**
  - `test_no_key_configured_allows_requests`.
  - `test_api_key_enforced`: with `JOBSIGNAL_API_KEY` set, no header → 401, wrong → 401, right → 200, and `/health` → 200 without the header.
  - `test_key_value_never_echoed`: 401 bodies don't contain the configured key.
  - `test_internal_errors_are_opaque`: monkeypatch a repository function to raise → 500 `{"detail":"internal error"}`, the body has no `Traceback` or exception text, and the log has the traceback.
  - `test_cors_off_by_default` (no `access-control-allow-origin` on a cross-origin GET) and `test_cors_allows_configured_origin`.
  - `test_non_loopback_requires_key`: `serve.main(["--host","0.0.0.0"])` → 2 without a key, and calls `uvicorn.run` (monkeypatched) with a key.
  - `test_loopback_hosts_accepted`: `127.0.0.1`, `::1`, `localhost`.
