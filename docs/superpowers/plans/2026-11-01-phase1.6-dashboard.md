# Phase 1.6: Dashboard Implementation Plan (rev. 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Streamlit alerting dashboard that reads only the API. It shows banded, grouped and explained alerts with trajectories (sparklines and Δs), a company view with trends, lazy postings, and data freshness.

**Architecture:**
- **API extension:** three read-only aggregate routes. Company composition and company trends are SQL aggregates; signal trends are recomputed with the detector's own functions. This way the UI never pulls rows to build charts.
- **API client:** a typed `ApiClient` (httpx) parses responses into the existing `jobsignal.api.schemas` models.
- **Pure logic:** `alerts.py` / `trends.py` (bands, grouping, copy, deltas, staleness) and `charts.py` (Altair specs).
- **UI:** `app.py` renders three tabs from cached calls. Postings load one page at a time on demand.

**Tech Stack:** Python 3.12, FastAPI (existing), Streamlit (+ Altair), httpx, pandas, pytest + `streamlit.testing.v1.AppTest` + FastAPI `TestClient`.

**Spec:** `docs/superpowers/specs/2026-11-01-phase1.6-dashboard-design.md` (rev. 2)

## Global Constraints

- **New dependencies:** `streamlit>=1.40,<2` and `altair` (lower bound = the version uv resolves, `<7`). Record the dependency-intake answers in the ledger.
- **Boundary:**
  - `jobsignal.dashboard.*` may import `jobsignal.api.schemas`, `jobsignal.config`, `jobsignal.weeks`, httpx, pandas, streamlit and altair.
  - It must never import `jobsignal.storage`, `jobsignal.signals`, `jobsignal.api.app/routes/deps` or `sqlalchemy`.
- **API additions:**
  - They follow Phase 1.5 rules: `GET` only, behind the `data` router (key + schema guards), queries in `storage/repository.py` / `signals/trend.py`, int64-bounded ids, and FiniteFloat values.
  - Each new route has a statement-count test that does not grow with input size.
- **No row loops in the UI:**
  - The dashboard never follows `next_cursor` automatically.
  - Each `/postings` request is caused by a render of a new filter set, or by one **Load more** click.
- **Constants:**
  - `YELLOW_Z = 3.0`, `RED_Z = 5.0`. `red` when |z| > 5; `yellow` when 3 ≤ |z| ≤ 5; otherwise `none`; z `None` → `none`.
  - `TREND_WEEKS = 8` (signal trends).
  - `COMPANY_TREND_WEEKS = 12`.
  - `PAGE_SIZE = 200`.
  - `CACHE_TTL_SECONDS = 60`.
  - `STALE_AFTER = timedelta(hours=36)`.
- **Gaps are gaps:** an uncovered week is `null` in the API and a gap in charts, never 0.
- **Settings:** `api_url: str = "http://127.0.0.1:8000"` (`JOBSIGNAL_API_URL`, http/https only, trailing `/` stripped); reuse `api_key`.
- **Exact copy:**
  - API down: `Cannot reach the JobSignal API at {base_url}. Start it with: uv run python scripts/run_api.py`
  - 401: `The API rejected the request: set JOBSIGNAL_API_KEY to the API's key.`
  - 503: the API `detail`, unchanged.
  - No runs: `No signal runs yet. Run: uv run python scripts/run_detect.py`
  - Empty run: `No alerts in this run with the current filters.`
  - Other errors: `Unexpected response from the API (HTTP {status}).`
  - Cold start: `Not enough history yet` (trend gaps).
  - Stale: `Stale data: {tokens}. Last scrape is older than 36 h or did not finish ok.`
- **Safety:**
  - No `unsafe_allow_html` / `components.html`.
  - Scraped strings are rendered only via `st.dataframe`/`st.text`.
  - Links only for `http(s)`.
  - The API key is never rendered, logged or put in an exception message.
  - No tracebacks reach the page.
- **Tests:** no live network. Client and app tests run against the real API via `TestClient(create_app(migrated_url))`.
- **Gates:** ruff check/format and pytest green on every task; gitleaks hook on every commit.

## Review Focus

1. **Trend disagrees with its alert.**
   - The last trend point must reproduce the stored z and observed value.
   - An uncovered week is a gap, never 0.
   - *(Task 2: `test_last_point_matches_detector`, `test_uncovered_week_is_gap`)*
2. **Row loops creeping back.**
   - One Companies render issues exactly one `/postings` request and stays within a fixed total.
   - Load more adds exactly one.
   - *(Task 6: `test_render_request_budget`, `test_load_more_appends_one_page`)*
3. **API down, key rejected, schema missing.** One pinned `st.error`, no exception element, and the key text appears nowhere on the page. *(Task 5: `test_api_down_shows_error`, `test_wrong_key_shows_auth_error_without_key`, `test_schema_missing_shows_hint`)*
4. **Hostile scraped text.** `<script>` / `javascript:` titles and URLs stay inert, and `unsafe_allow_html` is banned. *(Task 4: `test_safe_url`; Task 6: `test_scraped_text_never_rendered_as_markup`; Task 7: `test_no_unsafe_html_in_dashboard_source`)*
5. **Cold start and empty states.**
   - No runs, an empty run, a single run (no previous week), or all-null trends → pinned info copy and `None` deltas.
   - No `nan` / `None` text, and no crash on an empty `max()`.
   - *(Task 4: `test_deltas_*`, `test_previous_week_run_*`; Task 5: `test_no_runs_shows_info`; Task 6: `test_older_empty_run_shows_empty_info`)*

**Files:**

**Interfaces:**
- Produces:
  - `trend.TrendPoint(week_start: date, value: float | None, z: float | None)` (NamedTuple).
  - `trend.cell_trend(observed: pd.DataFrame, published: pd.DataFrame, available: dict[str, set[date]], *, detector: str, level: str, company: str, role_family: str | None, country: str | None, week: date, params: DetectorParams, weeks: int = TREND_WEEKS) -> list[TrendPoint]`.

    - For each point week `w`, take `as_of_w = datetime(w + 7 days, UTC)`:

    - A cell absent in that window → `TrendPoint(w, None, None)`.
  - `trend.trends_for_scores(session, scores: list[SignalScore]) -> dict[int, list[TrendPoint]]`:
    - Loads `opening_rows(session, company=c)` **once per distinct company** and `ok_snapshot_stats` **once**.
    - Uses each score's run params.
  - **Schemas:**
    - `TrendPointOut(week_start: date, value: FiniteFloat, z: FiniteFloat)`.
    - `SignalTrend(signal_id: int, metric: Literal["count", "share"], points: list[TrendPointOut])`.
  - **Route:** `GET /signals/trends?ids=1&ids=2`.
    - 1–50 ids, each `1..INT64_MAX`; else 422.
    - Returns `list[SignalTrend]` in request order, de-duplicated; unknown ids are omitted.
